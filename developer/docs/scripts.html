Scripts - Developer Guide

Users define scripts in JSON configuration. A script is an ordered list of commands; running it executes each command against the active Word document, stopping at the first failure.

How a script runs

RunScript.Handler → IScriptRepository.GetScript → Script.Execute(editor) → command.Execute(editor) → Word COM
Type Project Role
ScriptCommand Core.Application Abstract base. Each command runs on the one port it uses: most take Execute(IScriptDocumentEditor).
Script Core.Application Runs its commands in order; the first failure stops the script.
RunScript.Handler Core.Application CQS handler: looks the script up and runs it, then dispatches the events its steps raised, even when a step failed.
IScriptEvents Core.Application Where steps raise events (CustomPropertySet, CustomPropertyDeleted). They are held until the script ends, so scripts bound to them never start mid-run.
IScriptDocumentEditor Core.Application The one Word port a command may use — a composite of narrow ports.
WordObjectModelDocumentEditor WordAddIn The single implementation of that composite over the Word object model.
ScriptRepository Infrastructure.Persistence Reads scripts and mappings from ScriptOptions.
ScriptOptionsSetup Infrastructure.Persistence Binds ScriptOptions from configuration, deserialising each command with ScriptJson.Options.

Configuration

Scripts live under the ScriptOptions section of the configuration files found in the folders named by ConfigurationLocations (Shared, User).

{
  "ScriptOptions": {
    "Scripts": {
      "InsertText-Selection-Start": {
        "Comment": "Insert text at start of selection",
        "Commands": [
          {
            "$type": "InsertText",
            "Range": { "$type": "Selection", "SubRange": "Start" },
            "Options": { "Text": "[START]" }
          }
        ]
      }
    },
    "Mappings": {
      "InsertStartButton": {
        "Script": "InsertText-Selection-Start",
        "EnabledWhen": "Always",
        "VisibleWhen": "Always",
        "OnEvents": ["SnippetInserted"]
      }
    }
  }
}
  • $type names the command: the class <Type>ScriptCommand. It is required; a command without one fails to load.
  • Mappings attach a script to a ribbon button (EnabledWhen / VisibleWhen are rules-engine workflows) and, through OnEvents, to application events named by ApplicationEventNames.
  • Enums are written by name. ApplicationEventNames and DocumentElements also keep fixed numeric values, pinned by ScriptNameEnumsTests.

Serialisation contract

Every reader and writer of script JSON copies ScriptJson.Options:

var options = new JsonSerializerOptions(ScriptJson.Options) { WriteIndented = true };

It carries the $type discriminators — found by scanning the concrete ScriptCommand subclasses — and the enum-name converter. Building options without it reads every command as the abstract base and fails.

Schema

SchemaGenerator writes output/schemas/CoreConfiguration.schema.json from CoreConfiguration on every build, so a new command or option appears in the schema without further work. CoreConfiguration has one property per IUserOptions type; CoreConfigurationTests fails when one is missing.

Adding a command

  1. Create <Name>ScriptCommand : ScriptCommand under Core.Application/Features/Scripting/Commands/, with its options as properties carrying [Description] for the schema.
  2. Implement Execute(IScriptDocumentEditor documentEditor), narrowing to the one port it uses. The compiler refuses a command that does not.
  3. If it needs a Word capability the composite lacks, add a narrow port and extend IScriptDocumentEditor with it — the composite is the design control point. WordObjectModelDocumentEditor then implements it.
  4. Add the discriminator to ScriptJsonTests' published list, and write a test that runs Execute against a substituted IScriptDocumentEditor.

Nothing is registered: the discriminator, the schema entry and the dispatch all follow from the subclass.

Command reference

$type Does
ApplyFontFormatting / ClearFontFormatting Character formatting on a range
ApplyParagraphFormatting / ClearParagraphFormatting Paragraph formatting on a range
ApplyStyle Applies a named style
InsertText / InsertField Inserts at a range; InsertText supports PreventDuplicates and AfterInsertion cursor placement
DeleteCharacters Deletes characters within a range
EnforceCase Case conversion
SetCustomProperty / DeleteCustomProperty Document custom properties
RunMacro Runs a VBA macro
SelectElement Selects the next or previous DocumentElements element (DelimiterPair, ContentControl)
UpdateFieldCodes Updates field codes, per template pattern or across every story

Ranges (Range) are themselves polymorphic: Selection, Document, FirstParagraph, LastParagraph, Paragraph, each with a SubRange.
