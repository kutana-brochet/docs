GetQueryToolDataWithConfig COM Operation

Overview

A new COM operation GetQueryToolDataWithConfig that extends GetQueryToolData by allowing runtime configuration overrides. You can override any provider setting (Query, Filename, Timeout, FieldAliasOrder, etc.) without modifying the base configuration.

Purpose

This operation allows you to:

  1. Use an existing external data configuration by ID
  2. Override ANY provider setting at runtime via JSON
  3. Dynamically change queries, file paths, timeouts, and field mappings
  4. Apply configuration variations without creating multiple config entries

Usage

VBA Example - Override Excel Query

Dim result As String
Dim configOverrides As String

' Override the SQL query for an Excel provider
configOverrides = "{""Query"":""SELECT * FROM [Sheet1$] WHERE Status='Active'""}"

result = ComAddIn.Object.RunOperation("GetQueryToolDataWithConfig", "myExcelDataset", "JSON", configOverrides)

VBA Example - Override Field Aliases

Dim result As String
Dim configOverrides As String

' Override column display names
configOverrides = "{""FieldAliasOrder"":{""FirstName"":""Given Name"",""LastName"":""Family Name""}}"

result = ComAddIn.Object.RunOperation("GetQueryToolDataWithConfig", "myDatasetId", "CSV", configOverrides)

VBA Example - Override Multiple Settings

Dim result As String
Dim configOverrides As String

' Override query, timeout, and field aliases
configOverrides = "{""Query"":""SELECT TOP 100 * FROM [Data$]"",""Timeout"":30000,""FieldAliasOrder"":{""Email"":""Email Address""}}"

result = ComAddIn.Object.RunOperation("GetQueryToolDataWithConfig", "myDatasetId", "JSON", configOverrides)

VBA Example - Override JSON File Path

Dim result As String
Dim configOverrides As String

' Use a different JSON file
configOverrides = "{""Filename"":""C:\\Data\\AlternativeData.json""}"

result = ComAddIn.Object.RunOperation("GetQueryToolDataWithConfig", "myJsonDataset", "JSON", configOverrides)

Parameters

Parameter Type Description
datasetId String The ID of the configured external data source
format String Output format: "JSON" or "CSV"
configOverridesJson String JSON object with properties to override

    "ColumnA": "Display Name A",

Configuration Override Rules

  1. Merge Strategy: Overrides are merged with base configuration (overrides take precedence)
  2. Null/Empty Handling: Empty string or null JSON means no overrides (uses base config)
  3. Invalid JSON: Returns DomainErrors.ExternalData.InvalidConfigOverrides error
  4. Timing: Overrides are applied BEFORE dataset generation
  5. Type Safety: JSON is deserialized to the correct provider DTO type
  6. Partial Overrides: You only need to specify properties you want to override

Common Use Cases

Dynamic Filtering

Override the Query property to filter data based on runtime conditions:

Dim safeDept As String
' Escape single quotes to reduce SQL injection risk; also validate userDept against allowed values where possible.
safeDept = Replace(userDept, "'", "''")

configOverrides = "{""Query"":""SELECT * FROM [Data$] WHERE Department='" & safeDept & "'""}"

Environment-Specific Paths

Use different file paths for dev/test/prod:

If environment = "Production" Then
    configOverrides = "{""Filename"":""\\\\prod-server\\data.json""}"
Else
    configOverrides = "{""Filename"":""C:\\dev\\test-data.json""}"
End If

User-Specific Field Names

Customize column names based on user preferences:

configOverrides = "{""FieldAliasOrder"":{""DOB"":""Date of Birth"",""SSN"":""Social Security Number""}}"

Performance Tuning

Adjust timeout for slow data sources:

configOverrides = "{""Timeout"":60000}"  ' 60 seconds

Implementation Details

Architecture

The implementation follows Clean Architecture and DDD patterns:

  1. COM Interface (ComInterface.cs): Maps COM operation to application layer
  2. Application Layer (QueryToolComOperations.cs): Dispatches query with config JSON
  3. Query Handler (GetQueryToolStringWithConfig.cs): Passes config to repository
  4. Repository Layer (ExternalDataRepository.cs):
    • Retrieves base provider configuration
    • Parses JSON overrides
    • Merges overrides with base config (JSON merge)
    • Creates provider with merged configuration
    • Generates dataset using merged settings

Merge Process

Base Config (from appsettings.json)
         ↓
    Parse to JSON
         ↓
Merge with configOverridesJson → Override properties take precedence
         ↓
Deserialize to ProviderDto (JsonDto/ExcelDto/OutlookDto)
         ↓
Create Provider with merged config
         ↓
Generate Dataset

Error Handling

Domain errors:

  • DomainErrors.ExternalData.InvalidConfigOverrides: JSON parsing failed
  • DomainErrors.ExternalData.MissingDatasetIdConfiguration: Dataset ID not found
  • DomainErrors.ExternalData.FailedToLoad: Dataset generation failed
  • DomainErrors.ExternalData.FailedToCreateProvider: Provider creation failed

Logging

  • Configuration override application (info level)
  • Property merging details (debug level)
  • JSON parsing errors (error level)
  • Provider creation (info level)

Security Considerations

When using GetQueryToolDataWithConfig to override provider settings at runtime, treat all external input as untrusted and apply standard hardening practices:

  • SQL injection: If you override the Query setting, do not concatenate raw user input into SQL strings. Use parameterized queries or restrict user input to validated, whitelisted values (for example, fixed column names, sort orders, or filter options) before applying it to the query.
  • File/path traversal: If you override Filename or any file path–related setting, validate the path against an allowed base directory, reject paths containing .., and avoid accepting arbitrary absolute paths from untrusted sources.
  • General validation: Validate and sanitize all JSON override values before applying them, especially anything that influences data access, file system access, or execution of external tools.

Key Benefits

  1. Flexibility: Override any provider setting without config file changes
  2. Dynamic Queries: Adjust SQL queries at runtime via configuration overrides (ensure user input is handled safely; see Security Considerations)
  3. Environment Agnostic: Same config ID works across environments with path overrides
  4. User Preferences: Customize field names per user without multiple configs
  5. Testing: Easy to test different configurations programmatically
  6. No Config Pollution: Avoid creating many similar config entries
  7. Type Safety: Full DTO validation and type checking

Backward Compatibility

  • Base GetQueryToolData operation still works unchanged
  • Empty/null configOverridesJson behaves identically to base operation
  • Existing configurations are not affected
